## 2. Architecture

```text
Streamlit Add Incident
  -> file type detector
  -> modality extractor
  -> integration.integrate_records(...)
  -> llm_summarizer helpers
  -> confirmation preview
  -> cloud_deployment Supabase upload
  -> Supabase incidents table
  -> dashboard / management / final CSV export
```

Core architectural decisions:

- Streamlit is the UI and orchestration layer.
- Processing is synchronous for the classroom MVP.
- Extractors communicate with Integration through pandas DataFrames.
- Integration owns final row normalization, summary calls, and preview ID generation.
- Supabase persistence happens only after user confirmation.
- Raw files are not persisted to Supabase Storage.

## 3. Main Modules

| **Module** | **Responsibility** |
| --- | --- |
| `app.py` | Streamlit pages for upload, review, Combine Reports, dashboard, management, and downloads |
| `integration/integration.py` | Public `integrate_records(...)` workflow |
| `cloud_deployment/supabase_client.py` | Supabase create/read/update/delete operations for confirmed incident rows |
| `cloud_deployment/validators.py` | Supabase payload validation |
| `cloud_deployment/exporter.py` | Final nine-field CSV export from Supabase |
| `audio/`, `pdf/`, `images/`, `video/`, `text/` | Modality extractors that emit draft DataFrames defined in [specs.md](specs.md#3-modality-output-contract) |
| `llm_summarizer/summarizer.py` | `summarize_incident(row)` and `update_image_location(row)` |
| `llm_summarizer/prompts.py` | Prompt templates for OpenRouter summary and image-location assistance |
| `llm_summarizer/fallback.py` | Deterministic summary fallback |
| `llm_summarizer/schemas.py` | Summary input/output schema constants |

## 4. Public APIs

### Integration API

```python
def integrate_records(
    draft_df: pandas.DataFrame,
    source_type: str,
    existing_ids: Iterable = (),
    *,
    source_filename: str | None = None,
) -> pandas.DataFrame:
    """Return final rows with Incident_ID, Source, Event, Location, Time, Severity, Incident_Summary."""
```

### LLM Summarizer API

```python
def summarize_incident(incident_row: dict) -> dict:
    """Return incident_summary, summary_method, and summary_model."""


def update_image_location(image_row: dict) -> dict:
    """Fill missing image Location only when OCR evidence contains an explicit place."""
```

### Upload API

```python
final_df = integrate_records(draft_df, source_type, existing_ids, source_filename=filename)

# Called only after user confirmation.
upload_incidents(final_df, refresh_ids=True)
```

With `refresh_ids=True`, the upload layer re-reads Supabase IDs before validation and insert.

## 5. Data Models

### Integration Row

```text
Incident_ID, Source, Event, Location, Time, Severity, Incident_Summary
```

### Supabase Insert Payload

```text
incident_id, source, event, location, time, severity, incident_summary
```

### Supabase Stored Row and Final Export

```text
id, created_at, incident_id, source, event, location, time, severity, incident_summary
```

Supabase generates `id` and `created_at`. The app never inserts those two fields.

## 6. Supabase Table SQL

```sql
create table if not exists incidents (
  id bigint generated by default as identity primary key,
  created_at timestamptz not null default now(),
  incident_id text not null unique,
  source text not null,
  event text not null,
  location text not null,
  time text not null,
  severity text not null check (severity in ('Low', 'Medium', 'High', 'Unknown')),
  incident_summary text not null
);
```

## 8. Environment Variables

| **Variable** | **Required** | **Purpose** |
| --- | --- | --- |
| `SUPABASE_URL` | Yes | Supabase project URL |
| `SUPABASE_KEY` | Yes, unless one named key above is provided | Backward-compatible key name |
| `OPENROUTER_API_KEY` | No | Enables OpenRouter summaries |
| `ROBOFLOW_API_KEY` | Yes | Image detection/OCR key |

Store secrets in the host secret manager, GitHub Actions secrets, Streamlit secrets, or environment settings. Never commit credentials or raw evidence.

## 9. Technical Risks

| **Risk** | **Mitigation** |
| --- | --- |
| Heavy models run slowly inside Streamlit | Use short demo files and cached model downloads |
| LLM unavailable or invalid | Use deterministic fallback from `llm_summarizer/fallback.py` |
| LLM hallucination | Constrain prompts, validate output, and never allow LLM to override normalized fields |
| Supabase credentials missing or wrong | Show setup guidance and avoid crashing |
| Integration schema mismatch | Validate before Supabase insert |
| ID collision in concurrent use | Refresh IDs immediately before insert and document the class-demo assumption |
| OCR setup difficulty | Attempt OCR when available; otherwise degrade to `Unknown` fields |
| Video processing speed | Reject long clips and run detection only on configured sampled/motion frames |
| Roboflow unavailable | Use safe image defaults and continue |
| Dashboard stale data | Query Supabase directly for dashboard and final export |
